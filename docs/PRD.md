## 一、项目概述

- **Project Name**：issue_flow（issueFlow 问题提报平台）
- **Language**：中文（界面支持 zh-CN / en-US 双语，自 Phase 6 起）
- **产品定位**：一套前后端分离的缺陷记录与验证管理平台，覆盖问题记录、验证流程流转、用户权限管理、数据统计看板、标准化 RESTful API、Docker Compose 一键部署与可配置化界面。
- **四类角色**：提交者（Submitter）/ 开发人员（Developer）/ 测试人员（Tester）/ 管理员（Admin），基于 RBAC 进行访问控制（Phase 2 起演进为「权限码 + 角色-权限映射」体系）。

### 1.1 Product Goals（3 个清晰、正交目标）

1. **统一缺陷全生命周期管理**：将"提交 → 处理 → 验证 → 关闭"全流程线上化、可追溯，消除散落在 IM/邮件中的缺陷信息。
2. **基于角色的精细化协作**：四类角色权责分明，数据按权限隔离（提交者仅见自己数据，管理员全局可见），提升协作效率。
3. **数据驱动的质量洞察**：通过看板量化缺陷趋势、解决率与解决周期，辅助版本质量决策。

### 1.2 User Stories（基线）

1. **作为提交者**，我希望填写结构化表单（标题、描述、等级、标签、复现步骤、环境、截图/附件）提交缺陷并自动获得唯一编号，以便研发可快速复现与定位问题。
2. **作为开发人员**，我希望在工作台认领"待处理"缺陷并更新为"处理中/待验证"，以便让进度对团队透明。
3. **作为测试人员**，我希望对"待验证"缺陷执行验证、记录结果，通过则关闭、不通过则回退，以便保证出货质量。
4. **作为管理员**，我希望配置角色、分配权限、调整流程与界面主题，以便平台适配团队实际规范。
5. **作为任意登录用户**，我希望在统计看板按时间与版本筛选查看趋势与分布，以便掌握版本质量状况。

> Phase 2–7 各期的增量用户故事见第五、六章对应小节（如 Phase 7 的 US1–US11）。

| 看板图表导出 | 仅自己 | 全部 | 全部 | 全部 |
| 界面/主题/菜单配置 | ❌ | ❌ | ❌ | ✅ |

> 说明：所有写操作（状态变更、编辑）均强制记录操作人、时间戳、备注，写入操作历史。

### 2.2 权限体系演进（Phase 2 起）

- Phase 2：新增 `permission`（权限目录）与 `role_permission`（角色-权限映射）表；后端提供 `requirePermission(...)` 鉴权助手（ADMIN 放行全部）；新增角色管理页（角色 CRUD + 权限分配）；`requireAdmin()` 逐步被权限校验替换。
- Phase 5：新增 `flow:config` 权限码（流程配置）；新增 `system:reset`（数据初始化）并授予 ADMIN。
- Phase 7：新增 22 个权限码（`dict:*` / `file:*` / `config:*` / `redis:monitor` / `job:*` / `system:backup:export` / `infra:view` / `business:view`），写入 `permission` + `role_permission` 并授 ADMIN；个人中心接口只允许操作**当前登录用户自身**数据（接口不接受 userId 入参）。

## 三、验证流程状态机

### 3.1 状态集合

`待处理 (OPEN)` → `处理中 (IN_PROGRESS)` → `待验证 (PENDING_VERIFY)` → `验证通过 (VERIFIED)` → `已关闭 (CLOSED)`

### 3.2 允许的状态转移（含回退）

| 起始状态 | 目标状态 | 触发角色 | 备注 |
|---|---|---|---|
| 待处理 | 处理中 | 开发人员 / 管理员 | 即"认领"动作 |
| 处理中 | 待验证 | 开发人员 / 管理员 | 提交修复结果，附备注 |
| 待验证 | 验证通过 | 测试人员 / 管理员 | 验证结论=通过 |
| 待验证 | 处理中 | 测试人员 / 管理员 | **回退**：验证不通过，附回退原因 |
| 验证通过 | 已关闭 | 测试人员 / 管理员 | 终态 |
| 已关闭 | 待处理 | 管理员(可选) | 重新开启（如需支持） |
| 任意（异常） | 待处理 | 管理员 | 管理员强制重开/纠偏 |

> 约束：除管理员外，回退只能由测试人员从"待验证"退回"处理中"；其余正向流转按角色权限执行。每次流转必填备注（至少回退/关闭需填原因）。

### 3.3 操作历史追溯

- 每条记录包含：操作类型、源状态→目标状态、操作人、时间戳、备注。
- 支持按**操作人**、**时间范围**组合查询；支持查看单条问题的完整变更链。

### 3.4 流程配置演进（Phase 5 起）

- Phase 5：`flow_node`（节点）与 `flow_transition`（流转）两张表落库，现有 5 状态与 6 条硬编码流转**原样种子化**，`StateMachine` 改为数据驱动，流程配置页可视化流程图 + 节点/流转 CRUD（权限码 `flow:config`）。
- 基线两个开关 `flow_reject_enabled` / `flow_reopen_enabled` 语义在新模型中被等价承接（映射为对应流转的 enabled 标志）。

## 四、需求池总览（基线 P0/P1/P2）

> 以下为 Phase 1 基线（`docs/prd.md`）需求池；各期增量需求见第五、六章。

### P0 — 核心必做（MVP 必须交付）

- 问题记录模块：标题、详细描述、严重等级（致命/严重/一般/轻微）、分类标签、复现步骤、发现环境（OS/浏览器/应用版本/设备型号）、截图与附件上传；支持编辑/删除；系统自动生成唯一问题编号（如 `IS-20260101-0001`）。
- 验证流程模块：五状态流转 + 回退机制；每次变更记录操作人/时间/备注；单问题操作历史查看。
- 用户权限管理：四类角色与 RBAC 数据/功能隔离；JWT 认证登录。
- 基础统计看板：问题趋势图（按时间/版本）、状态分布、平均解决周期、解决率、严重等级占比。
- 统一登录页 + 管理后台与用户界面分离（基础版）。
- 基础 RESTful API：创建问题、更新问题信息、修改状态、查询详情；分页 + 多条件筛选 + API 认证。
- Docker Compose 一键部署（含 MySQL/Redis/后端/前端）。

### P1 — 重要（提升完整度）

- 操作历史支持按操作人 + 时间范围**组合检索**。
- 看板支持按时间范围与版本筛选。
- 看板图表导出为图片（PNG）或报表（Excel/PDF）。
- 主题色、页面布局结构可配置化。
- 附件上传支持常见类型与大小限制、预览（图片/文本）。
- 问题列表支持高级筛选（等级/标签/状态/版本/负责人）。

### P2 — 增强（差异化与体验）

- 菜单结构可配置化（拖拽/角色可见性）。
- 缺陷自动去重 / 相似度提示。
- 邮件/站内信通知（状态变更、被认领、被退回）。
- 看板支持自定义指标与多维度下钻。
- 操作历史导出审计日志。
- 移动端深度适配（原生手势/离线草稿）。

### 4.3 字典配置（R5.3）

- **管理对象**：按「字典类型」分组管理选项，本期至少覆盖「问题状态」「问题来源」两类；结构上须支持后续扩展新类型（如优先级、严重等级、标签分类）。
- **选项属性**：名称、编码、排序、启用状态、描述、是否系统预设（只读标记）。
- **系统预设保护**：预设项**不可删除**（按钮置灰 + 接口拦截），可编辑名称/排序、可停用；编码 code 不可修改（程序依赖）。
- **引用保护**：自定义项被问题引用时不可删除，提示「该选项下存在 N 条问题，无法删除，可改为停用」。
- **停用语义**：沿用 Phase 6 约定——表单下拉仅显示启用项；筛选下拉显示全部并对停用项加「(已停用)」后缀；历史数据正常回显。

### 4.5 备份数据（R8）

导出流程：`点击「备份数据」→ 确认弹窗（选范围 + 选格式 + 展示预计表数/条数）→ 确认 → 后端生成 → 浏览器下载 → 成功提示`

| 项 | 规格 |
| --- | --- |
| 范围 | ①全部数据（业务数据 + 配置数据）②仅核心配置数据（配置类表，不含 issue 等业务数据） |
| 格式 | JSON（结构化，含元信息头）/ SQL（可执行的 INSERT 语句集，元信息以注释头写入） |
| 文件名 | `backup_YYYY-MM-DD_HHMMSS.json` / `backup_YYYY-MM-DD_HHMMSS.sql`（服务器时间） |
| 元信息 | 系统版本号、导出时间、导出范围、格式版本、各表条数清单、（建议）导出人 |
| 状态反馈 | 备份中 loading + 按钮禁用；成功 `ElMessage.success`；失败展示后端返回的具体错误信息 |
| 安全 | ADMIN 角色 + 独立权限码；导出内容**不得包含明文密码**（密码字段应排除或保持 BCrypt 密文，见 Q6） |
| 边界 | 数据量大时需有超时/大小保护（见 Q6）；本期不做定时自动备份、不做在线还原 |
