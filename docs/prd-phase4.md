## 1. 产品目标

1. **问题定位粒度从「项目」细化到「模块」**：建立项目内的树形模块结构，让问题可以精确归属到任意层级的模块，提升缺陷分派与统计的精度。
2. **模块管理体验完整闭环**：增删改查、拖拽排序/层级调整、展开折叠、批量操作、依赖标记一站式完成，管理员无需借助外部工具维护项目结构。
3. **数据一致性守护（延续 Phase 3 理念）**：模块严格归属项目、问题模块选项随项目动态刷新、删除模块前校验关联问题，杜绝「问题挂在已删除/跨项目模块上」的脏数据。
4. **导航与入口进一步收敛**：前台顶栏去掉管理入口与样式定制按钮（仅保留左下角入口）；后台流程类功能（配置 + 监控）归拢到「流程管理」一级菜单，菜单语义更聚焦。

## 2. 用户故事（按 5 项需求）

### R1 — 项目模块树形结构（后台）
- **作为管理员**，我希望在项目下创建无限层级的子模块（如「支付中心 > 收银台 > 优惠券核销」），以便真实映射系统结构。
- **作为管理员**，我希望通过拖拽调整模块的排序与父子层级，而不是反复编辑表单。
- **作为管理员**，我希望批量选中多个模块一次性删除或移动到另一个父模块下，减少重复操作。
- **作为管理员**，我希望标记「模块 A 依赖模块 B」，以便评估某模块的问题可能波及的范围。
- **作为管理员**，我希望展开/折叠任意节点并记住浏览状态，在大树中快速聚焦。

### R2 — 问题提交时的模块关联（前台）
- **作为提交者/开发/测试**，我在提交问题选定项目后，希望在「所属模块」下拉中以层级缩进形式看到该项目完整模块树，快速选中问题所在模块。
- **作为提交者**，我希望在模块下拉中输入关键字模糊搜索，命中项高亮且父级路径自动展开，避免在深层树里逐级找。
- **作为提交者**，当我切换关联项目时，希望模块选项立即刷新为新项目的模块树，且已选模块被清空，防止跨项目错挂。

### R3 — 前台顶栏入口收敛（前台）
- **作为普通用户**，我不希望前台顶栏出现「管理后台」按钮和主题色取色器，界面更干净。
- **作为管理员**，我仍能通过前台**左下角**（侧栏底部）入口一键进入管理后台。

### R4 — 「流程管理」一级菜单（后台）
- **作为管理员**，我希望后台侧栏出现「流程管理」一级菜单，其下包含「流程配置」和「流程监控」两个子菜单，流程类功能集中一处。
- **作为管理员**，原有 `/admin/flow-config`、`/admin/flow-monitor` 深链仍可访问，不产生 404。

### R5 — 功能联动约束（前后端）
- **作为系统**，模块数据必须归属于唯一项目；跨项目引用模块一律拒绝。
- **作为管理员**，删除（或批量删除）模块时，若该模块（含其子孙模块）下存在关联问题，系统应阻止并明确提示数量，避免问题失去归属。

## 3. 需求池（P0 / P1 / P2）

> P0 本期必做；P1 重要（本期或紧接）；P2 增强（后续迭代，避免过度设计）。每条均可验收。

### P0 — 核心必做

| 编号 | 条目 | 验收标准 | 影响面 |
|---|---|---|---|
| R1-1 | 新建 `module` 表（邻接表模型：`project_id` + `parent_id` 自引用 + `sort` + `name` + `description`，沿用 BaseEntity 软删），提供模块 CRUD 接口 | 可在任意项目下创建 ≥4 层子模块；同级按 `sort` 升序展示；同一父级下模块名唯一 | 后端新表 + 新 Controller/Service |
| R1-2 | 后台「项目管理」内提供模块树管理面板（详见 §4.1）：树形展示 + 节点增删改 + 展开/折叠 | 树正确渲染层级；新增/编辑/删除单节点即时生效 | 前端新组件 + 后端接口 |
| R1-3 | 拖拽排序与层级调整（`el-tree` draggable），拖拽落点持久化（更新 `parent_id` + 同级 `sort` 批量重排） | 拖拽到兄弟间→改排序；拖拽入其他节点→改父级；刷新后保持；禁止拖成自己子孙的子节点（防环） | 前端 + 后端排序接口 |
| R1-4 | 批量操作：多选（复选框）→ 批量删除、批量移动（选目标父模块） | 批量删除走 R5-2 校验；批量移动禁止移到自身/子孙下 | 前端 + 后端批量接口 |
| R2-1 | `issue` 表新增 `module_id`；提交问题表单（`IssueForm.vue`）新增「所属模块」下拉，以层级缩进（或 `el-tree-select`）展示当前项目完整模块树 | 选项文案含层级路径感（缩进或「父 > 子 > 孙」）；提交后 `issue.module_id` 正确落库；问题列表/详情回显模块路径 | 前端 + 后端加列/新接口 |
| R2-2 | 模块下拉支持关键字模糊搜索：命中项**高亮**匹配片段、**自动展开**父级路径 | 输入关键字后树过滤为命中节点及其祖先链；命中文本高亮；清空关键字恢复全树 | 纯前端（基于已加载树） |
| R2-3 | 项目切换联动：切换「关联项目」后清空已选模块并重新加载该项目模块树；未选项目时模块下拉禁用 | 切项目后 `moduleId` 置空；下拉选项为新项目模块；无项目时禁用且有占位提示 | 纯前端（调既有模块树接口） |
| R3-1 | 移除前台 `UserLayout.vue` 顶栏的 `<LayoutSwitchEntry variant="topbar">` 与 `el-color-picker`（该位置全部样式定制按钮），清理关联死代码（`themeColor`/`onThemeChange` 等） | 前台顶栏右侧仅剩头像下拉；左下角（侧栏底部）入口仍在且 ADMIN 可切后台；后台 `AdminLayout` 不受影响 | 纯前端 |
| R4-1 | `menu` 表种子新增一级菜单「流程管理」（`type=2`，建议 `path=/admin/flow`，无权限码即登录可见，与「系统管理」父级同范式）；「流程配置」「流程监控」`parent_id` 指向它 | 后台侧栏出现「流程管理 > 流程配置 / 流程监控」；顶级不再单独出现二者；旧深链 `/admin/flow-config`、`/admin/flow-monitor` 仍可访问 | 种子 SQL（幂等），无前端代码改动 |
| R5-1 | 模块归属约束：模块接口全部以 `projectId` 为查询/写入边界；问题保存时后端校验 `module.project_id == issue.project_id` | 传入他项目模块 id 时返回业务错误码；模块树接口只返回指定项目的模块 | 后端 |
| R5-2 | 删除模块校验：删除（含批量）前统计该模块**及其子孙**下 `deleted=0` 的关联问题数，>0 则阻止并提示「该模块（含子模块）下存在 N 个关联问题，无法删除」 | 有关联问题→删除失败+提示；无关联→删除成功（子孙一并软删）；复用 `BizException` + 前端拦截器提示范式 | 后端 + 前端确认弹窗 |

## 4. UI 设计稿（文字/结构描述）

### 4.1 模块树管理面板（后台，R1）

**入口**：`views/admin/ProjectManage.vue` 项目行操作列新增「模块管理」按钮 → 打开右侧抽屉（`el-drawer`，size≈560px，标题「模块管理 — {项目名}」）。
> 备选：独立页面 `/admin/projects/:id/modules`。推荐抽屉——不新增菜单/路由，与 Phase 3「整体风格设置」抽屉交互一致。

**抽屉内部结构（自上而下）**：

```
┌─ 模块管理 — 核心交易系统 ──────────────────────── ✕ ─┐
│ [＋ 新增根模块]  [批量删除] [批量移动]   🔍 搜索模块…   │
│ ──────────────────────────────────────────────────── │
│ ☐ ▾ 支付中心            [＋子] [✎] [依赖 2] [🗑]      │
│ ☐   ▾ 收银台            [＋子] [✎] [依赖 0] [🗑]      │
│ ☐     · 优惠券核销       [＋子] [✎] [依赖 1] [🗑]      │
│ ☐ ▸ 订单中心            [＋子] [✎] [依赖 0] [🗑]      │
│ ──────────────────────────────────────────────────── │
│ 提示：拖拽节点可调整排序与层级                          │
└──────────────────────────────────────────────────────┘
```

- **树组件**：`el-tree`，`draggable`、`show-checkbox`、`default-expand-all=false`、`node-key=id`；`allow-drop` 拦截「拖入自身子孙」。
- **行内操作**（悬浮显示）：＋子（在该节点下新增子模块）、✎（编辑名称/描述）、依赖 N（P1，打开依赖设置弹层）、🗑（删除，触发 R5-2 校验，二次确认文案含关联问题检查结果）。
- **新增/编辑弹窗**：字段仅 `名称`（必填，≤50 字，同父级下唯一）、`描述`（选填，≤200 字）。
- **批量删除**：勾选 ≥1 节点后可用；确认弹窗列出所选模块名；任一节点（含子孙）有关联问题则整体阻断并提示（策略见 §5-Q5）。
- **批量移动**：勾选后点击 → 弹窗内以树形单选目标父模块（含「根级」虚拟节点）；目标不可为所选节点自身或其子孙。
- **顶部搜索框**：本地过滤树（命中节点 + 祖先链保留，命中文本高亮），与 R2-2 前台搜索逻辑复用同一工具函数。

### 4.2 问题表单的模块选择器（前台，R2）

位置：`components/IssueForm.vue`「关联项目」表单项**之后**新增「所属模块」表单项（选填，宽度与项目下拉一致）。

- **控件**：推荐 `el-tree-select`（Element Plus 内置，满足树形 + 层级缩进 + `filterable` 关键字过滤 + 命中自动展开父级；无新依赖）。
  - `check-strictly=true`（任意层级节点均可直接选中，父模块本身也可作为归属）。
  - 选中后输入框回显完整路径「父模块 > 子模块 > 孙模块」。
  - `filter-node-method` 实现模糊匹配；命中文本以 `<span class="hl">` 高亮（自定义节点插槽）。
- **联动行为**：
  | 场景 | 行为 |
  |---|---|
  | 未选择项目 | 模块下拉 `disabled`，placeholder「请先选择关联项目」 |
  | 选定项目 | 调 `GET /api/modules/tree?projectId=xxx` 加载该项目模块树 |
  | 切换项目 | 立即清空 `model.moduleId`，重新加载新项目模块树 |
  | 清空项目 | 清空 `moduleId` 并禁用模块下拉 |
  | 项目无模块 | 下拉展示空态「该项目暂无模块」 |
- **编辑回显**（P1 R2-5）：按 `initial.moduleId` 回显路径。

### 4.4 菜单结构（R4）

**改动后后台侧栏（menu 表 type=2）**：

```
概览
问题管理
项目管理
流程管理            ← 新增一级（icon 建议 Operation/Connection，sort=4）
 ├─ 流程配置        ← parent_id：系统管理 → 流程管理（permission=flow:config）
 └─ 流程监控        ← parent_id：0 → 流程管理（permission=flow:view）
系统管理
 ├─ 组织管理 / 菜单管理 / 用户管理 / 角色管理   （「流程配置」移出）
```

- 「流程管理」父菜单不设 `permission`（登录可见，子项按权限码过滤），与「系统管理」父级同范式。
- 路由 path 保持 `/admin/flow-config`、`/admin/flow-monitor` 不变（深链兼容，沿用 Phase 3 R5 决策）；仅菜单归属变化，`SideMenu.vue` 零改动。
- 种子 SQL 幂等（子查询解析父 id，参照 `V20260730_issueflow_phase3.sql` 写法）。

|---|---|---|
| Q1 | **模块树存储模型**：邻接表（`parent_id` 自引用，与 `menu` 表同范式）还是路径串（`path` 物化路径）？ | 推荐**邻接表**：与既有 `menu`/`SideMenu` 范式一致、拖拽改父只需更新一行；「查子孙」用内存组树（单项目模块量级可控），删除/统计时递归收集子孙 id。不建议引入 MySQL 8 递归 CTE 之外的复杂度 |
| Q2 | **「无限层级」是否需要软上限**？超深层级 UI 缩进会溢出 | 建议技术上不限、产品上软限 **10 层**（超出时创建接口报错），前台选择器缩进 UI 以 10 层为设计上限 |
| Q3 | **拖拽排序持久化模型**：拖拽一次落库一次，还是「保存」批量提交？ | 推荐**即拖即存**（一次拖拽 = 1 个接口调用：`{moduleId, targetParentId, orderedSiblingIds}`），失败回滚树 UI；与 el-tree 事件模型契合 |
| Q4 | **依赖标记语义**：单向（A 依赖 B）还是双向（A 与 B 相关）？仅展示标记还是有约束行为（如删除被依赖模块时警告）？ | 建议**单向**「A 依赖 B」+ 仅展示、防环校验，无其他约束行为；因语义待拍板，整体列 **P1**（R1-5/R1-6），请主理人确认是否提入本期 |
| Q5 | **批量删除遇到部分节点有关联问题**：整体阻断，还是跳过有问题的、删除其余的？ | 推荐**整体阻断**（原子性、提示明确：「以下模块存在关联问题：xxx(3)、yyy(1)，请先处理」），避免"删了一半"的中间态 |
| Q6 | **删除父模块的级联策略**：子孙模块一并删除，还是提升到祖父级？ | 推荐**级联软删**（含子孙），R5-2 校验范围本就含子孙关联问题，语义自洽；确认弹窗需写明「将同时删除 N 个子模块」 |
| Q7 | **R3 移除前台取色器后，前台主题色能力是否整体下线**？（`store/theme`、`localStorage['if_theme']`、Phase 3 遗留的前台主题逻辑） | 推荐本期仅移除**入口**，保留 store（已存的主题色继续生效），P1 再评估是否清理；避免改动面扩散。若主理人希望前台恢复默认色并清理死代码，请明示 |
| Q8 | **模块是否有「状态」（启用/停用）字段**？ | 建议本期**不加**（YAGNI）；项目已有启停机制，模块用「删除」即可 |
| Q9 | **问题的 `module_id` 是否必填**？存量问题无模块归属如何展示 | 建议**选填**（渐进式），存量与未选模块的问题展示「—」；若要求必填会阻碍无模块项目的问题提交 |
| Q10 | **「流程管理」父菜单的 path**：虚拟父级（如 `/admin/flow`，无对应路由，仅作 el-sub-menu index）是否可接受？ | 「系统管理」父级 path=`/admin/system` 有 SystemLayout 路由兜底；「流程管理」建议同样给 `path=/admin/flow` 但**不建路由**（el-sub-menu 的 index 不触发导航，点击仅展开）。若架构师认为需兜底路由，可加 redirect 到 flow-config |
