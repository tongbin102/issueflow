# ADR 003: 问题状态机与流转规则

- 状态：**Accepted**（已采纳）
- 日期：2026-07-30
- 决策人：架构师 高见远 / 产品经理 许清楚

## 上下文（Context）

问题需经历完整生命周期：待处理 → 处理中 → 待验证 → 验证通过 → 已关闭，并需支持**测试回退**与**管理员重开**。要求：

- 流转必须受角色约束（如回退仅测试/管理员、重开仅管理员）。
- 每次流转必须记录操作人、时间戳、备注，形成可追溯操作链。
- 流程需可配置，但 MVP 阶段不要求可视化编排。

## 决策（Decision）

- **状态机实现**：`handler.StateMachine` 维护 **6 条转移表**（`List<Transition>`），每条含 `from / to / roles / action / configKey / remarkRequired`：
  | 起始 → 目标 | 触发角色 | 动作 | 备注 |
  |---|---|---|---|
  | OPEN→IN_PROGRESS | D / A | CLAIM | — |
  | IN_PROGRESS→PENDING_VERIFY | D / A | SUBMIT_FIX | — |
  | PENDING_VERIFY→VERIFIED | T / A | VERIFY_PASS | — |
  | PENDING_VERIFY→IN_PROGRESS | T / A（需 `flow_reject_enabled`） | VERIFY_REJECT | 必填原因 |
  | VERIFIED→CLOSED | T / A | CLOSE | 写 `closed_at` |
  | CLOSED→OPEN | A（需 `flow_reopen_enabled`） | REOPEN | — |
- **非法转移**：`StateMachine.isAllowed` 返回 false → `IssueFlowService` 抛 `BizException(STATUS_TRANSITION_DENIED, 1002)`。
- **可配置开关**：回退/重开受 `sys_config` 开关 `flow_reject_enabled` / `flow_reopen_enabled` 控制（`SysConfigService.isEnabled`），由 `FlowConfig` 页面切换。
- **历史写入**：每次流转经 `IssueHistoryService.record(issueId, action, from, to, operatorId, remark)`；详情页/列表展示 `StatusTimeline`。
- **前端联动**：`StatusFlowButtons` 依据 当前状态 + `userStore.roles` + 流程开关 计算可用按钮，回退/关闭弹框填写备注。

## 后果（Consequences）

- **正向**：流转规则集中、角色与开关可校验；操作链完整可追溯（操作人/时间/源→目标/备注）。
- **可配置**：MVP 仅提供"回退/重开"开关级配置，满足 PRD P0；后续可扩展更多状态节点。
- **已知限制**：
  - 状态机仅实现 **6 条固定转移**；PRD/架构中提到的"管理员从任意态强制置 OPEN 纠偏"**当前未实现**（仅 `CLOSED→OPEN` 重开）。
  - 重开无次数上限；关闭时间（`closed_at`）在重开时清空。
- **对齐**：`IssueFlowController` 仅暴露 `status` / `reopen` / `flow/config` 接口，转移表即唯一事实来源。
