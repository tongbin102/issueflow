## 1. 项目信息

- **Language**：中文
- **Programming Language**：前端 Vue3 + Element Plus + Vite；后端 Spring Boot 3.2（本 PRD 仅关注产品层面）
- **Project Name**：issue_flow
- **原始需求复述**：构建一套前后端分离的缺陷记录与验证管理平台，覆盖问题记录、验证流程流转、用户权限管理、数据统计看板、标准化 RESTful API、以及 Docker Compose 一键部署与可配置化界面六大模块。四类角色（提交者/开发人员/测试人员/管理员）基于 RBAC 进行访问控制。

## 2. 产品定义

### 2.1 Product Goals（3 个清晰、正交目标）

1. **统一缺陷全生命周期管理**：将"提交 → 处理 → 验证 → 关闭"全流程线上化、可追溯，消除散落在 IM/邮件中的缺陷信息。
2. **基于角色的精细化协作**：四类角色权责分明，数据按权限隔离（提交者仅见自己数据，管理员全局可见），提升协作效率。
3. **数据驱动的质量洞察**：通过看板量化缺陷趋势、解决率与解决周期，辅助版本质量决策。

### 2.2 User Stories

1. **作为提交者**，我希望填写结构化表单（标题、描述、等级、标签、复现步骤、环境、截图/附件）提交缺陷并自动获得唯一编号，以便研发可快速复现与定位问题。
2. **作为开发人员**，我希望在工作台认领"待处理"缺陷并更新为"处理中/待验证"，以便让进度对团队透明。
3. **作为测试人员**，我希望对"待验证"缺陷执行验证、记录结果，通过则关闭、不通过则回退，以便保证出货质量。
4. **作为管理员**，我希望配置角色、分配权限、调整流程与界面主题，以便平台适配团队实际规范。
5. **作为任意登录用户**，我希望在统计看板按时间与版本筛选查看趋势与分布，以便掌握版本质量状况。

## 4. 验证流程状态机

### 4.1 状态集合

`待处理 (OPEN)` → `处理中 (IN_PROGRESS)` → `待验证 (PENDING_VERIFY)` → `验证通过 (VERIFIED)` → `已关闭 (CLOSED)`

### 4.2 允许的状态转移（含回退）

| 起始状态 | 目标状态 | 触发角色 | 备注 |
|---|---|---|---|
| 待处理 | 处理中 | 开发人员 / 管理员 | 即"认领"动作 |
| 处理中 | 待验证 | 开发人员 / 管理员 | 提交修复结果，附备注 |
| 待验证 | 验证通过 | 测试人员 / 管理员 | 验证结论=通过 |
| 待验证 | 处理中 | 测试人员 / 管理员 | **回退**：验证不通过，附回退原因 |
| 验证通过 | 已关闭 | 测试人员 / 管理员 | 终态 |
| 已关闭 | 待处理 | 管理员(可选) | 重新开启（如需支持） |
| 任意（异常） | 待处理 | 管理员 | 管理员强制重开/纠偏 |

> 约束：除管理员外，回退只能由测试人员从"待验证"退回"处理中"；其余正向流转按角色权限执行。每次流转必填备注（至少回退/关闭需填原因）。

### 4.3 操作历史追溯

- 每条记录包含：操作类型、源状态→目标状态、操作人、时间戳、备注。
- 支持按**操作人**、**时间范围**组合查询；支持查看单条问题的完整变更链。

## 5. 需求池（Requirements Pool）

### P0 — 核心必做（MVP 必须交付）

- 问题记录模块：标题、详细描述、严重等级（致命/严重/一般/轻微）、分类标签、复现步骤、发现环境（OS/浏览器/应用版本/设备型号）、截图与附件上传；支持编辑/删除；系统自动生成唯一问题编号（如 `IS-20260101-0001`）。
- 验证流程模块：五状态流转 + 回退机制；每次变更记录操作人/时间/备注；单问题操作历史查看。
- 用户权限管理：四类角色与 RBAC 数据/功能隔离；JWT 认证登录。
- 基础统计看板：问题趋势图（按时间/版本）、状态分布、平均解决周期、解决率、严重等级占比。
- 统一登录页 + 管理后台与用户界面分离（基础版）。
- 基础 RESTful API：创建问题、更新问题信息、修改状态、查询详情；分页 + 多条件筛选 + API 认证。
- Docker Compose 一键部署（含 MySQL/Redis/后端/前端）。

### P1 — 重要（提升完整度）

- 操作历史支持按操作人 + 时间范围**组合检索**。
- 看板支持按时间范围与版本筛选。
- 看板图表导出为图片（PNG）或报表（Excel/PDF）。
- 主题色、页面布局结构可配置化。
- 附件上传支持常见类型与大小限制、预览（图片/文本）。
- 问题列表支持高级筛选（等级/标签/状态/版本/负责人）。

### P2 — 增强（差异化与体验）

- 菜单结构可配置化（拖拽/角色可见性）。
- 缺陷自动去重 / 相似度提示。
- 邮件/站内信通知（状态变更、被认领、被退回）。
- 看板支持自定义指标与多维度下钻。
- 操作历史导出审计日志。
- 移动端深度适配（原生手势/离线草稿）。

## 6. UI 结构（页面树）

```
登录页 (/login)
├── 用户界面 (User Portal)
│   ├── 工作台首页（我的待办 / 我提交的问题）
│   ├── 问题列表（筛选/分页/查看详情）
│   ├── 问题详情（信息 + 复现 + 附件 + 操作历史）
│   ├── 新建问题（结构化表单）
│   └── 我的统计（个人维度看板）
├── 管理后台 (Admin Console)
│   ├── 问题管理（全部数据 + 高级筛选）
│   ├── 验证流程监控（状态流转总览）
│   ├── 用户与角色管理（RBAC 配置）
│   ├── 流程配置（状态/流转规则）
│   ├── 统计看板（全局指标 + 筛选 + 导出）
│   └── 系统设置（主题色 / 布局 / 菜单配置）
└── 公共
    └── 404 / 无权限页
```

> 界面要求：简洁现代、响应式（桌面 + 移动端）；主题色与布局结构可配置。

## 7. 待确认问题（Open Questions — 需用户拍板）

1. **流程配置具体配什么？** 管理员"流程配置"是仅启用/禁用回退与重开，还是允许自定义额外状态节点（如"挂起/已拒绝"）？是否支持按问题分类走不同流程？
2. **附件存储策略？** 附件是直接存本地卷（Docker volume）还是对接对象存储（MinIO/OSS）？单文件大小上限与总容量如何设定？是否需要病毒扫描？
3. **看板导出格式与权限？** 图表导出默认支持 PNG / Excel / PDF 哪些格式？导出是否受角色数据范围限制（如提交者仅导出自己数据）？
4. **唯一编号规则？** 编号采用 `IS-日期-自增` 还是 `项目前缀-模块-序号`？是否需要支持多项目/多团队隔离命名空间？
5. **"已关闭"是否允许重开？** 状态机中"已关闭→待处理"是否对管理员开放？是否设置重开次数上限或需审批？
