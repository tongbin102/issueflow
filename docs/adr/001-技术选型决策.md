# ADR 001: 技术选型决策

- 状态：**Accepted**（已采纳）
- 日期：2026-07-30
- 决策人：架构师 高见远 / 产品经理 许清楚

## 上下文（Context）

我们需要为「issueFlow 缺陷记录与验证管理平台」确定全栈技术选型。约束与偏好如下：

- **用户偏好**：后端使用 Java Spring Boot 全栈体系，前端使用 Vue3 + Element Plus；团队对这两套技术栈最熟悉，便于长期维护。
- **生成环境限制**：本机**无 JDK 17**，因此后端代码只能产出、**无法在本机本地编译验证**；Node.js 环境可用，前端可本地构建。
- **部署诉求**：希望尽量降低部署门槛，支持一键拉起完整依赖（MySQL / Redis / 后端 / 前端）。
- **能力诉求**：需要 RBAC、状态机流转、看板统计、标准 RESTful API、可配置主题界面。

## 决策（Decision）

- **后端**：Spring Boot 3.2 + MyBatis-Plus 3.5.x + MySQL 8 + Redis 7 + JWT（jjwt 0.12.x，HS256）+ Spring Security 6 + Knife4j（OpenAPI3）+ EasyExcel。
- **前端**：Vue3 + Element Plus + Vue Router 4 + Pinia + Axios + ECharts + Vite 5。
- **部署**：Docker Compose 一键编排（`docker-compose.yml`，含 mysql / redis / backend / frontend 四服务），后端/前端各自 Dockerfile，前端经 nginx 托管。
- **分层**：后端严格分层 `Controller / Service / Mapper / Entity`，横切 `security / common / util / config / handler`；前端分层 `api / components / views / store / router / layouts / utils`。

## 后果（Consequences）

- **正向**：技术栈成熟、生态完善；MyBatis-Plus 减少约 70% CRUD 样板；Spring Security 6 `SecurityFilterChain` 天然契合前后端分离无状态；Docker Compose 降低部署门槛。
- **限制**：后端因本机无 JDK 17 **未能本地编译**，需用户在自有环境 `docker compose up` 或 JDK 17 下 `mvn package` 实测；架构与代码已严格对齐，风险低。
- **已验证**：前端已在本机 `npm run build` 通过。
- **托管**：MySQL / Redis 由 compose 托管（数据卷持久化），无需用户单独安装数据库。
- **成本**：状态机与流程开关以"开关级"配置（MVP），非完全可视化流程编排；后续可迭代增强。
